# _runtime\vc-win7-x64 —— 打包时用的 VC++ 运行库(Win7 专用那一套)

打包 Windows 7 版(`paofen_win7.spec` / `build_exe_win7.ps1`)时, 会把这几个文件
**替换/补进** exe 内的 `onnxruntime\capi\`、`pyclipper\`、`numpy\*` 等目录 —— 因为
Windows 加载子目录里的扩展时, 先找「它自己所在目录」再找 `System32`, 只有放在它旁边
才轮得到; 否则会用目标机 `System32` 里那份(可能过旧)VC 运行库, 报:

```
ImportError: DLL load failed while importing onnxruntime_pybind11_state: 找不到指定的程序。
```

| 文件 | 版本 | 来源 |
|------|------|------|
| `msvcp140.dll` | 14.29.30158 (VS2019) | `shapely.libs\msvcp140-<hash>.dll`, 已把导入表里的改名依赖(`vcruntime140_1-<hash>.dll`)改回标准名 |
| `vcruntime140.dll` | 14.28.29914 | Python 3.8.10 安装目录(随 CPython 分发, 支持 Win7) |
| `vcruntime140_1.dll` | 14.29.30158 (VS2019) | `shapely.libs\vcruntime140_1-<hash>.dll` |

## 为什么是这个版本

- **必须 < 14.40**: VS2019(14.2x/14.3x)是最后一个官方支持 Windows 7 目标的工具链;
  实测把本机 `System32` 里 **14.51**(VS2022/Win11 时代)那套放进包内, 在 Win7 上**照样**
  报「找不到指定的程序」。
- **必须够新**: onnxruntime 1.14.1 的 `onnxruntime_pybind11_state.pyd` 需要 `MSVCP140.dll`
  的 **204 个符号** + `VCRUNTIME140.dll` 19 个 + `VCRUNTIME140_1.dll` 1 个; 目标机
  `System32` 里那份如果是 VC2015/2017 时代的旧版, 就会缺符号。14.29 实测 **204/204** 全有。
- 这些文件都是**可再分发**的运行时(与 VC++ Redistributable 同一份内容)。

## 怎么更新这一套

1. 从 VS2019 的 VC 运行库(如 `vc_redist.x64.exe` 14.29 解出来的
   `Microsoft.VC142.CRT\x64\`)取 `msvcp140.dll` / `vcruntime140.dll` / `vcruntime140_1.dll`;
2. 或继续用 wheel 私藏副本(见上表来源), 但**必须**用
   `check_exe_compat.demangle_runtime_copy()` 处理过(否则内部依赖还是改名版, 会报
   「找不到指定的模块」);
3. 放好后重新打包 `.\build_exe_win7.ps1` —— 打包时会自动校验:
   - 版本必须 < 14.40, 否则**直接报错**(不再发出起不来的包);
   - 必须覆盖包内二进制对它的全部引用, 否则也报错。
